## Findings

### AUD-01 · P1 · Model guards allow changed money, outcomes and unsupported claims

**Owners:** Tevin; Harry reviews action boundaries. **Evidence:** direct validator probes and static call-path review.

`backend/resolve/conversation/rewrite.py:88` strips decimal separators and ignores signs when comparing number sets. `preserves_facts('LKR 80.00', 'LKR 8000')`, `preserves_facts('LKR -70.00', 'LKR 70.00')` and `preserves_facts('Your action is pending.', 'Your action succeeded.')` all return true. `backend/resolve/conversation/answer.py:84` also accepts `grounded('Your refund is approved.', 'Contact support for review.')`. Domain recognition does not cover all suffixes, allowing an unexpected `.io` URL against a different supplied URL.

The localization path in `conversation/service.py:303` can rewrite deterministic responses, including action wording. This does not bypass the provider authorization gate, but can misrepresent amounts, consent or completion to the customer. The probes establish validator weakness, not that a live model produced these replies.

**Recommended fix/acceptance:** keep proposal, consent, money and operation outcomes in deterministic reviewed templates or immutable slots; compare signed decimal values with units and exact allowed URLs. Reject changed status, polarity, value associations and new claims. Add adversarial regression cases and actual-model qualification; lexical matching alone cannot prove semantic grounding.

### AUD-02 · P1 · Investigation mutation bypasses Origin/CSRF checks

**Owner:** Harry. **Evidence:** API reproduction.

`backend/resolve/app/case_api.py:178` authenticates the customer but does not use the customer mutation guard. A valid cookie with an untrusted Origin and no CSRF token received **200** and reached the facade. Investigations persist evidence/revisions and affect proposal eligibility. Cookie SameSite behavior limits some cross-site attack paths; this finding does not assert universal browser exploitability.

**Recommended fix/acceptance:** use the existing mutation guard; verify missing/incorrect CSRF and untrusted Origin fail before any facade mutation. Include every browser write route in a shared security matrix.

### AUD-03 · P1 · Abandoned turn claims can block subsequent conversation turns

**Owners:** Harry storage/claims; Tevin retry semantics; Jayith client recovery. **Evidence:** static lifecycle trace.

`conversation/storage.py:116` reserves a durable claim before checking the expected version at line 142. `services/turn_claims.py:48` rejects a different turn ID whenever an unfinished claim exists, even after its lease expires. `release_turn` at line 90 only releases the lease. A stale-version error or abandoned failed turn can therefore leave all newly generated IDs returning `CONVERSATION_BUSY`. The frontend keeps failed input/ID in React state, which is lost on reload.

Same-ID retry with a refreshed version can recover: expected_version is excluded from the turn fingerprint. The bug is abandonment/new-ID recovery, not an assertion that every retry is permanently blocked.

**Recommended fix/acceptance:** check stale versions before reservation under the same concurrency protection, define safe recovery of abandoned claims and persist/recover pending client IDs. Preserve downstream idempotency. Disposable PostgreSQL tests must cover stale submission followed by a new turn, reload, expired lease, crash after side effect and competing retries.

### AUD-04 · P1 · Late microphone permission can leave a live audio track after leaving the call

**Owner:** Jayith. **Evidence:** Node fake-media reproduction plus code review.

`frontend/src/voice/audio.ts:53` awaits getUserMedia before assigning the stream; `close()` around line 166 only stops a currently assigned stream. If the user leaves while permission is pending, then grants permission, startup continues against the closed context and the newly acquired track is not stopped. Probe result: `startResult='closed context', microphoneTrackStopped=false`.

**Recommended fix/acceptance:** use a closed/generation guard, stop late streams and clean up every failure after acquisition. Test close-before-grant, denial, worklet failure and repeated start/stop; then verify with a real browser microphone.

### AUD-05 · P2 · Documented escalation API is absent

**Owner:** Harry; Jayith validates the UI. **Evidence:** runtime route comparison and authenticated **404** probe.

`docs/contracts.md:76` defines `POST /cases/{id}/escalations`; the runtime has no handler. `frontend/src/routes/customer/CasePanel.tsx:182` calls the corresponding client method, so its review request fails. The conversation fallback in `conversation/resolve_adapter.py:204` uses action proposal creation and does not persist the supplied escalation reason.

**Recommended fix/acceptance:** implement the agreed scoped/idempotent proposal endpoint through the existing facade, persist the reason and expose the proposal for normal confirmation. Verify customer review request, replay/conflict, reason retention, confirmation and dashboard delivery. Do not treat proposal creation as delivery.

### AUD-06 · P2 · Agent cookie takes precedence over a valid customer session

**Owner:** Harry. **Evidence:** API reproduction.

`backend/resolve/app/auth.py:118` chooses the agent cookie whenever it exists for shared reads. Valid customer cookie plus revoked agent cookie returns **401 SESSION_EXPIRED** on an operation read. Separate customer/agent login can therefore break customer case/operation/receipt access; two valid cookies can also select an unintended scope.

**Recommended fix/acceptance:** define explicit caller realm selection for shared reads without silently elevating customer requests. Cover customer-only, agent-only, dual-valid and either-expired cookie combinations, including cross-account/run denial.

### AUD-07 · P2 · Spoken action acceptance does not trigger operation tracking

**Owners:** Harry projection; Jayith browser; Tevin TurnResult parity. **Evidence:** direct projection probe and frontend trace.

`backend/resolve/app/voice_api.py:190` projects `result.get('operation_status')`, while the actual TurnResult exposes `operation_ids`. Passing a real result-shaped dictionary with an operation ID produces null status and no operation IDs. `frontend/src/routes/customer/VoiceShell.tsx:45` starts conversation refresh/tracking only when operation_status is truthy. Spoken acceptance can create an operation without the in-call UI tracking completion. Text/tap and later chat reload have separate recovery paths.

**Recommended fix/acceptance:** reconcile the canonical projection and browser refresh trigger; obtain scoped operation references without implying success at acceptance. Test spoken accept -> pending -> terminal result/receipt, duplicate callback and failure while staying in the call.

### AUD-08 · P2 · Review updates before CRM ticket delivery are not synchronized later

**Owner:** Harry. **Evidence:** static worker/outbox trace.

`services/review.py:249` creates a sync job only for an already DELIVERED ticket. `services/operations.py:408` can deliver the ticket later without backfilling earlier review events. A note/disposition saved during CRM outage can remain local after delivery, with no queued synchronization.

**Recommended fix/acceptance:** retain deferred review intent or backfill ordered review events when delivery succeeds. Verify review-before-delivery, multiple notes, closure, retry and lost response with exactly-once provider effect in disposable PostgreSQL.

### AUD-09 · P2 · Last finished operation overwrites aggregate case status

**Owner:** Harry. **Evidence:** static operation/proposal trace.

`services/operations.py:412` derives case status from the current operation alone. Multiple actions can be proposed over a case lifetime, including while another is pending. A later successful action can set OPEN despite another pending operation or an earlier review-required outcome. A VAS change must not hide a historical dispute.

**Recommended fix/acceptance:** derive status from all relevant operations, evidence and unresolved review reasons under consistent locking. Test both completion orders for success/failure, pending/success and review-ticket/success, including an independently closed review.

### AUD-10 · P2 · Voice grant provisioning does not enforce request idempotency

**Owner:** Harry. **Evidence:** static route/contract review.

`app/voice_api.py:430` provisions a new binding/grant without consuming the documented Idempotency-Key. Retrying after a lost response can create multiple bindings/provisioning calls.

**Recommended fix/acceptance:** persist scoped key/fingerprint/outcome, define consumed/expired-grant replay behavior, reject changed-body reuse and test simultaneous retries and lost response. External Voice changes, if needed, require their separately agreed repository/branch.

### AUD-11 · P2 · Unexpected API errors lose the error envelope and correlation header

**Owner:** Harry. **Evidence:** API reproduction.

`app/main.py:152` handles known domain/validation errors, while `app/observability.py:88` logs and rethrows unexpected failures. A provider RuntimeError returned **500 text/plain 'Internal Server Error'** without X-Request-Id, violating the normal client contract and weakening diagnostics.

**Recommended fix/acceptance:** map expected dependency failures and supply a safe catch-all error envelope/correlation header without leaking exception text. Test provider and database faults, logging redaction and browser handling.

### AUD-12 · P2 · Contract-required authentication throttling is absent

**Owner:** Harry. **Evidence:** static auth/middleware inspection; no load test.

`docs/contracts.md:24` requires throttling; guest/session/login routes in `app/auth.py` have no effective limiter. Unbounded guest creation permits database growth and login endpoints accept repeated attempts.

**Recommended fix/acceptance:** bounded per-client/identity controls, explicit trusted-proxy policy, expiry and stable rate-limit errors. Test limits, recovery and isolation. Use a deployment-appropriate shared mechanism if running multiple workers; avoid an unnecessary new service for the demo.
